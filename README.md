# ROS2 移动机器人导航作业报告

## 1. 作业目标

本作业基于 ROS 2 Humble 导航工程，在给定的 15 m × 15 m 迷宫地图中，实现移动机器人的自主导航与路径跟踪。

作业要求机器人从固定起点 **(0.900, 0.900)** 出发，通过 RViz 指定目标点，完成从全局路径规划到机器人运动控制的完整导航流程，最终到达指定终点 **(14.100, 14.100)**。

工程已提供地图、仿真环境、A* 全局路径规划器和行为树等基础模块。本次作业主要完成控制器插件的参数配置与路径跟踪算法实现，并通过仿真验证导航效果。

## 2. 系统结构

本工程采用模块化的 ROS 2 导航架构，主要包括以下模块：

1. **地图与代价地图模块**：加载迷宫地图，生成全局代价地图及局部代价地图，为路径规划提供环境信息。
2. **全局路径规划模块**：使用 A* 算法，根据机器人当前位置和目标位置生成全局路径，并通过 `/global_path` 发布。
3. **导航决策模块**：通过行为树和导航接口组织导航任务，完成目标接收、路径规划及控制流程调度。
4. **路径跟踪控制模块**：由 `ControllerServer` 加载自定义 `PidController` 插件，根据规划路径和机器人当前状态计算速度指令。
5. **机器人仿真模块**：接收速度指令，更新机器人运动状态，并发布里程计等信息。
6. **RViz 可视化模块**：用于设置导航目标、观察规划路径和检查机器人运动过程。

导航流程如下：

```text
RViz 设置目标点
       ↓
导航决策与行为树
       ↓
A* 全局路径规划
       ↓
发布 /global_path
       ↓
ControllerServer
       ↓
PidController 路径跟踪
       ↓
发布 /sentry/cmd_vel
       ↓
机器人仿真运动
       ↓
里程计与 RViz 状态更新
```

## 3. 控制器实现

### 3.1 插件接口

本次实现位于：

`src/sp_controller_server/plugins/pid_controller.cpp`

控制器遵循工程提供的 `ControllerPlugin` 接口，主要实现以下三个函数：

- `configure()`：读取控制器参数，保存节点、TF 缓冲区及坐标系信息，并初始化控制器状态。
- `setPlan(path)`：接收并保存全局规划路径。
- `computeVelocityCommands(pose, velocity)`：根据全局路径和机器人当前状态计算速度指令，并返回 `TwistStamped` 消息。

通过 `pluginlib` 加载控制器插件，保持原有导航框架不变。

### 3.2 路径跟踪方法

当前版本采用**基于前视点选择与比例控制的路径跟踪方法**，借鉴 Pure Pursuit 的前视思想，通过位置误差计算平面速度。

主要步骤如下：

**第一步：获取全局路径。**

控制器通过 `setPlan()` 保存 A* 规划得到的路径。路径点位于 `map` 坐标系下。

**第二步：获取机器人当前位姿。**

通过 TF 查询 `map` 到 `base_link` 的变换，获取机器人在地图坐标系下的位置以及航向角。这样可以避免直接将局部里程计坐标与全局路径坐标混用。

**第三步：寻找最近路径点。**

遍历全局路径，计算各路径点与机器人当前位置之间的欧氏距离，确定最近路径点的索引。

**第四步：选择前视目标点。**

从最近路径点开始沿路径向前搜索，选取与机器人当前位置距离达到设定前视距离的路径点，作为当前控制目标。

前视点选择有助于控制器关注机器人前方的路径，而不是始终只追踪最近的路径点。

**第五步：计算位置误差。**

设机器人当前位置为 \((x_r,y_r)\)，前视目标点为 \((x_t,y_t)\)，则位置误差为：

\[
e_x=x_t-x_r
\]

\[
e_y=y_t-y_r
\]

**第六步：计算平面速度。**

当前版本采用比例控制，根据位置误差计算地图坐标系下的速度：

\[
v_x^{map}=K_p e_x
\]

\[
v_y^{map}=K_p e_y
\]

随后对平面速度进行限幅，避免输出速度超过设定的最大速度。

**第七步：转换速度坐标系。**

将地图坐标系下的速度转换为机器人 `base_link` 坐标系下的速度。设机器人航向角为 \(\theta\)，则：

\[
v_x^{base}=\cos\theta\,v_x^{map}
+\sin\theta\,v_y^{map}
\]

\[
v_y^{base}=-\sin\theta\,v_x^{map}
+\cos\theta\,v_y^{map}
\]

最后，将计算得到的平面速度写入 `TwistStamped` 消息，由控制服务器发布给仿真机器人。

需要说明的是，虽然插件名称为 `PidController`，且当前版本读取了 \(K_p\)、\(K_i\)、\(K_d\) 参数，但实际速度计算使用的是比例项 \(K_p\)，积分项和微分项尚未参与控制。因此，当前实现应准确描述为**前视点选取 + P 控制**，而非完整 PID 控制。

### 3.3 参数配置

控制器参数位于：

`src/sp_nav_bringup/config/nav_params.yaml`

当前采用的参数如下：

| 参数 | 当前值 | 作用 |
|---|---:|---|
| `base_frame_id` | `base_link` | 机器人本体坐标系 |
| `lookahead_distance` | 0.8 m | 前视目标点选择距离 |
| `kp` | 1.5 | 比例控制增益 |
| `ki` | 0.0 | 积分增益，当前未参与计算 |
| `kd` | 0.1 | 微分增益，当前未参与计算 |
| `max_speed` | 1.0 m/s | 平面速度模长上限 |

其中，前视距离影响路径跟踪的平滑程度和转弯时的切角情况；比例增益影响速度对位置误差的响应程度；最大速度限制用于约束机器人运动速度。

## 4. 工程编译与运行

### 4.1 环境要求

- Ubuntu 22.04
- ROS 2 Humble
- colcon
- 工程提供的机器人仿真与 RViz 环境

### 4.2 编译工程

在工程根目录执行：

```bash
colcon build --symlink-install
```

编译完成后加载工作空间环境：

```bash
source install/setup.bash
```

### 4.3 启动仿真与导航

进入启动脚本所在目录：

```bash
cd bash
./sim_nav_all_start.sh
```

启动脚本会打开相应终端，启动 TF、导航系统和机器人仿真。

### 4.4 执行导航任务

1. 等待机器人仿真、地图、规划器、控制器和 RViz 正常启动。
2. 在 RViz 中使用 `2D Goal Pose` 工具设置导航目标。
3. 将目标设为作业要求的终点 \((14.100,14.100)\)。
4. 观察全局路径是否生成，以及机器人是否沿路径运动并到达目标。
5. 通过 RViz 中的路径显示和机器人状态检查导航执行情况。

## 6. 调试过程与问题分析

### 6.1 控制器参数缺失

**现象：** 启动时提示缺少 `PidController.lookahead_distance`，控制器插件加载失败。

**原因：** 在 `configure()` 中增加了参数读取逻辑，但 `nav_params.yaml` 中尚未配置对应参数。

**解决方法：** 在 `controller_server.ros__parameters.PidController` 下补齐 `lookahead_distance`、`kp`、`ki`、`kd` 和 `max_speed` 等参数，重新编译并启动，随后控制器成功加载。

### 6.2 四元数转换代码编译失败

**现象：** 使用 `std::ignore` 调用 `tf2::Matrix3x3::getRPY()` 时，编译器提示无法将该参数转换为 `double&`。

**原因：** `getRPY()` 要求 roll、pitch 和 yaw 均通过可写变量的引用传入，不能使用 `std::ignore` 代替。

**解决方法：** 定义 `roll` 和 `pitch` 两个 `double` 变量，再将它们与 `yaw` 一起传入 `getRPY()`。修改后，控制器编译通过。

### 6.3 路径话题在设置目标前已经存在

**现象：** 尚未点击导航目标时，执行 `ros2 topic list` 已经可以看到 `/global_path`。

**原因：** 话题是否存在取决于节点是否创建并注册了对应的发布器，不代表已经执行了有效的路径规划。

**验证方法：** 设置导航目标后观察 RViz 中的路径显示，并通过 `ros2 topic echo /global_path --once` 检查路径消息及其坐标系。测试中确认路径的 `frame_id` 为 `map`。

### 6.4 全局路径与里程计坐标系不同

**现象：** `/global_path` 使用 `map` 坐标系，而 `/Odometry` 的 `header.frame_id` 为 `lidar_odom`，`child_frame_id` 为 `base_link`。

**原因：** 全局路径和局部里程计描述机器人状态时使用的参考坐标系不同，不能直接混用位置数据。

**解决方法：** 控制器通过 TF 查询 `map` 到 `base_link` 的变换，获取用于路径跟踪的机器人位姿，并在计算速度后将地图坐标系下的速度转换为本体坐标系下的速度。

## 7. 总结

本次作业在现有 ROS 2 导航工程的基础上，完成了控制器参数配置、插件加载和路径跟踪算法实现。通过前视点选择确定当前控制目标，利用比例控制计算平面速度，并结合 TF 坐标变换与速度限幅，使机器人能够根据 A* 生成的全局路径执行导航。

仿真结果表明，机器人已经能够从指定起点出发并成功到达指定目标，验证了当前导航链路和控制器实现的基本有效性。

本次实践进一步加深了对 ROS 2 插件机制、全局路径规划、TF 坐标变换、速度指令发布以及移动机器人路径跟踪流程的理解。
